# app/src/features — 화면 단위 기능

화면(라우트)마다 폴더 하나. 각 폴더는 `XxxPage.tsx`, 그 화면에서만 쓰는 컴포넌트와 훅을 가진다.

## 예정 구성과 라우트

| 폴더 | 라우트 | 내용 |
| --- | --- | --- |
| `auth/` | `/login` | 로그인, 로그아웃, 인증 필요 라우트 보호 |
| `home/` | `/` | 상단 카드, 3D 장면(`scene`), 하단 단계 바, 핀·확대 화면, 우측 상세 카드, 알람 표시 |
| `tank/` | `/tanks`, `/tanks/:id` | 이력 그래프, 기준값 설정, 알람 이력 |
| `robot/` | `/robot` | 관절 값, 수동 조작, 오류 로그, 사이클 통계 |
| `conveyor/` | `/conveyor` | 속도 설정, 이력 |
| `compressor/` | `/compressor` | 압력·온도 그래프, 설정, 점검 이력 |
| `alarms/` | `/alarms` | 활성·이력 목록, 확인 처리, 누르면 해당 기기 페이지로 |
| `settings/` | `/settings` | 화질 모드(기본/저사양), 계정, 앱 정보 |
| `cctv/` | 오버레이 | 카메라 선택, 발급받은 주소를 `<video>`로 재생 |

사이드바 순서: 홈, 탱크, 로봇팔, 컨베이어, 압축기, 알람, 설정. 권한 없는 메뉴는 숨기거나 비활성화.

## 정보 배치 기준 (명세 3절)

- 홈 = "지금 정상인가": 매번 확인하고 이상이면 바로 조치할 정보. 기기당 숫자 2개 정도.
- 확대 화면 = "이 기기 상태가 어떤가": 기기를 눌렀을 때 바로 필요한 정보 + 간단한 조작 + "상세 보기".
- 기기 페이지 = "왜 그런가, 설정은, 이력은": 가끔 보거나 신중해야 하는 정보 + 위험 조작.
- 새 정보를 추가할 때 이 기준으로 어느 단계에 둘지 먼저 정한다.

## home/ 규칙

- 상단 카드: 함수율(수분), 전체 적재율, 시스템 상태.
- 하단 단계 바: 집기, 이동, 놓기, 압축. 로봇 `phase`·`status`에 연결. 정지·오류·연결 끊김은 색으로 강조. 사이클 시간처럼 계속 바뀌는 숫자는 넣지 않는다.
- 상세 카드: 적재율, 부피(용량), 상태, 위치. 사진 대신 장면 그림. 무게 없음.
- 알람은 단계와 상관없이 홈에서 색·아이콘으로 강조, 누르면 해당 기기 페이지.
- 3D가 실패하거나 저사양이면 같은 정보를 2D 배치도로 보여 줄 수 있게 장면과 오버레이 UI를 분리한다(1단계에서는 2D 홈으로 먼저 완성).

## cctv/ 규칙

- 버튼을 누르면 별도 화면(오버레이)으로 열고, 열려 있는 동안 `ui.cctvOpen = true`로 3D 그리기 루프를 멈춘다.
- 재생 주소는 만료되는 서명 주소다. 만료되면 다시 발급받는다. 로봇 조작과 함께 볼 때는 WebRTC 우선, HLS는 참고용(수 초 지연).

## 공통 규칙

- 화면은 store 선택자와 `api` 훅으로만 데이터를 얻는다.
- 위험 조작은 기기 페이지에서만(`components/controls`의 `context='page'`).
- 화면을 떠날 때 그 화면이 연 구독(관절 값 등)을 해제한다.
