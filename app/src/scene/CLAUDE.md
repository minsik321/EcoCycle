# app/src/scene — 홈 3D 장면 (react-three-fiber)

밝은 저폴리 아이소메트릭 장면이다. **저사양 태블릿에서 끊김 없이 도는 것**은 여전히 지켜야 할 바닥선이지만,
그 위에서는 **시각 품질도 1차 목표**다(2026-10-13 재설계, `docs/decisions.md` 참조). 둘을 양립시키는 장치가
화질 3단계(`config/quality.ts`)다. 실제 태블릿 측정은 `/scene-demo`(features/home/SceneDemoPage)로 한다.

## 화질 3단계 (`config/quality.ts`)

| 티어 | 그림자 | bloom | 패널(UI) | 오브젝트 수 | 용도 |
| --- | --- | --- | --- | --- | --- |
| `high` | 실시간 소프트 섀도우 | 켬 | `backdrop-blur` 글라스 | 전체 디테일 | 성능 여유가 있는 기기 |
| `standard` | 그림자 라이트 1개, 낮은 해상도 | 끔 | 주요 패널만 블러, 나머지 단색 | 중간 | 기본값 |
| `low` | 미리 그린 바닥 그림자 텍스처 | 끔 | 블러 없는 단색 패널 | 줄임 | 저사양 태블릿 안전판, 기존 2단계 규칙과 동일 |

- 접속 시 짧은 FPS 프로브로 자동 선택하고, 설정 화면에서 사용자가 바꿀 수 있다. 선택은 `localStorage`에 기억한다(기존 "화질 모드 기기 기억" 결정과 같은 자리).
- `low`는 안전판이다: 새 연출을 넣을 때 `low`에서 기존 2단계 성능 원칙(아래)이 깨지지 않는지 먼저 확인한다.

## 장면 구성 (명세 1절, 재설계 진행 중)

현재 구현: 벽 한쪽을 잘라낸 방 안에 탱크 4개(A1, A2, B1, B2), 중앙 로봇팔, 로봇 옆에서 압축기까지 이어지는 긴 컨베이어 하나(Section Z), 압축기.

목표(단계적으로 확장, 각 단계 끝에 스크린샷으로 확인): 입고 도로·게이트·계중대 → 수납 섹터 4개(기존 탱크와 같은 기기, 외형만 벙커형으로) → 로봇팔·컨베이어 → 압축기·결속 → 출하장(지게차 이동). 비즈니스 값(회사·등급·배합·압력)은 전부 서버/모의서버에서 오며 장면은 받은 값을 그릴 뿐이다. 트럭·지게차·작업자의 구체적 동선은 시각 연출이며 서버 센서 값이 아니다.

위치·카메라 프리셋은 `config/sceneLayout.ts`에서 읽는다.

## 구조

```
scene/
├── HomeScene.tsx       Canvas(직교 카메라, frameloop="demand"), 조명, 화질 모드 적용. 데이터는 모두 props
├── frame.tsx           FrameDriver: 움직임이 있을 때만, 초당 maxFps번까지만 그리기를 요청. paused면 요청하지 않음
├── stats.ts            그린 횟수(프레임 측정용). 3D 라이브러리를 import하지 않는다
├── layout.ts           설정값 → 장면 좌표 (탱크 위치, 핀·카메라 기준점, 전체 보기 확대)
├── materials.ts        공용 재질·지오메트리, 바닥 그림자 텍스처(미리 그림, low 티어용)
├── camera/CameraRig    아이소메트릭 카메라. 드래그 팬·휠/핀치 줌·제한 회전(±35도)과 기기별 프리셋 이동, 선택 대상을 따라가는 추적
├── objects/            Room, Tank(수위 → 파지 조각 수), Conveyor, Compressor, RobotArm, chunks(조각 자리 계산). 확장분(게이트·계중대·건물·출하장)도 여기 추가
├── actors/             스스로 움직이는 것(트럭, 지게차, 작업자) — 연출용, 서버 비즈니스 값을 담지 않는다
├── robot/              chain(관절 사슬 정의, three 미사용), kinematics(끝점 위치), jointSource(fixed·demo·live)
├── pins/PinProjector   기기 위치를 화면 좌표로 바꿔 HTML 핀(features/home/ScenePins)에 써 넣음
├── scene.logic.test.ts     계산 로직 테스트
└── scene.objects.test.tsx  RobotArm·Tank를 그래픽 없이 만들어 보는 테스트
```

- 처음 화면 묶음에 3D 라이브러리가 딸려 오지 않게 한다: `features`가 정적으로 import해도 되는 것은 `stats.ts`, `robot/chain.ts`, `robot/jointSource.ts`와 타입뿐이다. 나머지는 `HomeScene`을 lazy로 불러올 때 함께 온다. 고친 뒤 `npm run build`로 메인 묶음 크기를 확인한다.
- 많아진 오브젝트(트럭, 작업자, 바닥 타일 등)는 `InstancedMesh`나 병합 지오메트리로 그린다. 재질·지오메트리는 공유하고 종류별로 하나씩만 만든다.
- `JointSource`의 progress(단계+진행률) 방식은 아직 없다. 서버가 진행률을 주는 형식이 명세에 없어서다(`docs/decisions.md`).

## 성능 원칙 (명세 4절, 반드시 지킬 것 — 화질 3단계로 적용 방식만 달라진다)

1. 저폴리, 공유 재질. `low`는 불투명 재질과 미리 그린 그림자만 쓴다. `standard`/`high`는 `MeshStandardMaterial`, 실시간 소프트 섀도우, 은은한 발광(창문·경광등·상태등), `high`에 한해 bloom을 허용한다. 투명·유리 재질은 3D 오브젝트 자체가 아니라 UI 패널(CSS `backdrop-blur`)에만 쓴다.
2. 움직임이 없으면 그리지 않는다: `frameloop="demand"` + 필요할 때 `invalidate()`. 화면이 숨겨지거나 CCTV가 열리면 그리기 루프 정지. **연결 끊김이면 로봇뿐 아니라 트럭·지게차·컨베이어·압축기까지 모든 움직임을 정지**하고 마지막 자세에서 멈춘다(추측으로 애니메이션하지 않는다).
3. 초당 30프레임 이하로 제한하고, 상한은 화질 티어마다 다를 수 있다(`config/quality.ts`). 센서 값이 빨라도 화면 반영은 묶어서.
4. 탱크 안 파지, 바닥 타일, 트럭·작업자처럼 수가 많은 것은 `InstancedMesh`로. 상한은 `config/quality.ts`.
5. 재질·지오메트리는 공유하고 매 프레임 새 객체를 만들지 않는다(`useFrame` 안에서 `new` 금지).
6. 연출(그림자·bloom·새 오브젝트)을 추가하기 전에 가장 낮은 사양의 실제 태블릿에서 30분 이상 구동해 프레임·발열을 확인한다. `low` 티어가 이 확인의 기준이다.

## 카메라·조작

- 드래그로 팬, 휠/핀치로 줌, 고정된 틀기 범위 안에서(±35도) 제한 회전. 모두 부지 경계로 클램프한다. `OrbitControls`를 그대로 쓰지 않고 범위를 제한하는 래퍼를 둔다.
- 트럭·섹터·로봇·컨베이어·압축기·지게차·베일 등 오브젝트를 누르면 카메라가 그 대상으로 글라이드하고, 움직이는 대상이면 계속 따라간다. 펄싱 링과 라벨로 선택을 표시한다.
- 지역 전환(입고·섹터·선별·압축·출하)과 검색은 `features/home`이 카메라 API를 호출해 제어한다. `scene`은 지역·검색 UI를 모른다.

## 로봇팔

- `RobotArm`은 **입력과 분리**한다: `JointSource`에서 관절 각도·그리퍼를 받아 그리기만 한다. 입력을 바꿔도 그리기 코드는 그대로.
- 링크 길이·축 방향·영점·각도 범위는 `config/robotModel`(서버 `/robots/{id}/model`로 덮어씀)에서.
- 관절 값은 `useFrame`에서 `realtime/jointBuffer.sample()`로 읽는다. Redux 구독으로 받지 않는다.
- 연결 끊김(`connection.status === 'offline'`)이면 팔을 마지막 자세에서 멈추고 끊김 표시를 띄운다. 추측으로 움직이지 않는다. `RobotArm`은 `frozen`이면 다시 그려지더라도(카메라 이동 등) 관절 값을 새로 읽지 않는다.
- 후퇴 순서: live → progress → demo. demo는 실제와 어긋날 수 있으니 화면에 "시연 동작"임을 표시한다.

## 기타

- 장면 안 글자는 최소화한다. 라벨은 HTML 오버레이(`features/home`)로, 오브젝트에 붙어 함께 움직이되 작게 유지하고 겹치지 않게 배치를 조정한다(핀과 같은 방식).
- 3D 모델 파일을 쓰게 되면 glTF + 압축, 폴리곤 수를 `docs/decisions.md`에 기록한다. 지금은 모델 파일 없이 코드로만 만든다.
- 5단계 확장(압축기 이후 공정)은 2단계 테스트에서 여유가 확인된 경우에만 — 단, 이번 재설계로 출하장(지게차)까지는 2단계 범위에 포함된다(사용자 요청, `docs/decisions.md`).
