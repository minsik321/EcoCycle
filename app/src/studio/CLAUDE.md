# app/src/studio — 홈의 "스튜디오" 탭 (실험적 고화질 시안)

홈 3D 영역의 두 번째 탭이다. "기본" 탭(`scene/` + `features/home`)을 그대로 둔 채, 홈 화면을 **처음부터 새로** 만든 시안이며
목표는 **최대한의 시각 품질**이다. 유지할지는 사용자가 결과를 보고 정한다(2026-10-14 사용자 요청, `docs/decisions.md`).

## 창작의 자유 (이 폴더에서는 아래를 따르지 않는다)

이 탭은 다음 규칙에 **묶이지 않는다.** 이 폴더에서 작업할 때는 이 파일만 기준으로 삼고, 아래 문서의 시각·배치·성능 규칙은 무시한다.

- 기존 시각 디자인과 디자인 토큰(`styles/index.css`의 색·모서리·그림자, Tailwind 클래스, `components/common`의 패널·카드)
- `app/src/scene/CLAUDE.md`의 성능 원칙과 화질 3단계(저폴리·불투명 재질만·미리 그린 그림자·초당 30프레임 제한·움직임 없으면 그리지 않기·InstancedMesh 강제·카메라 ±35도 제한 등)
- 루트 `CLAUDE.md`의 공통 규칙 7번(화질 3단계)과 "범위를 벗어난 카메라 조작" 금지, `app/CLAUDE.md`의 화면 기준(태블릿 우선·48dp·호버 금지)
- `app/src/features/CLAUDE.md`의 홈 배치 규칙(상단 카드 구성, 단계 바 구성, 정보 배치 기준)
- `docs/dashboard-spec.md`의 화면 모양·성능 원칙 절 (API·값 규칙은 그대로 따른다)

허용되는 것: 후처리(주변 차폐·빛 번짐·심도), 실시간 그림자, 환경광, 투명·유리 재질, 유리 UI, 입자, 자유로운 카메라 이동·확대·회전,
glTF 모델, 새 색·재질·배치·핀·패널. 기존 재질·팔레트·배치·핀·패널은 "정말 그게 최선일 때만" 다시 쓴다.
저사양 태블릿을 위해 미리 줄이지 않는다. **최신 노트북·데스크톱 GPU 기준으로 먼저 만들고, 성능은 재서 보고한다**(줄이는 것은 이 탭을 유지하기로 한 뒤).

## 고정 규칙 (이 탭에 남아 있는 규칙은 이것뿐이다)

1. **"기본" 탭을 깨지 않는다.** 기본 탭의 모습·동작·테스트는 그대로여야 한다. 스튜디오 코드는 `app/src/studio/`에만 두고, 탭을 열 때만 lazy로 불러온다. **메인 묶음이 커지면 안 된다.**
   - `features/home`이 정적으로 import해도 되는 것은 없다. `lazy(() => import('../../studio'))`만 쓴다. 스타일도 `studio.css`(스튜디오 묶음과 함께 내려받음)에만 둔다.
   - 고친 뒤 `npm run build`로 처음 내려받는 묶음(index와 그것이 정적으로 import하는 조각의 합)을 확인한다.
2. **데이터는 기존 store·실시간 계층에서만 온다**(`/scene-demo`에서는 `demo/demoData.ts`의 예시 원본). 프론트에 업무 로직을 두지 않는다:
   번호판 → 회사 → 섹터 배정, 등급, 수분, 배합비, 압력은 서버 값이다. 서버가 아직 주지 않는 숫자가 필요하면 **명세와 모의 서버에 먼저 추가**하거나, 화면에 **"예시 데이터"라고 분명히 표시**한다.
3. **연결 끊김:** 연결이 끊기면 **모든 움직임을 멈추고** "연결 끊김"과 마지막 수신 시각을 보여 준다. 추측을 실제처럼 움직이지 않는다.
4. **조작:** 기존 조작 컴포넌트(`components/controls`)와 권한만 쓴다. 위험 조작은 기기 페이지에 둔다. 비상정지처럼 보이는 버튼을 만들지 않는다.
5. **화면이 숨겨지거나 CCTV가 열리면 그리기를 멈춘다.**

이 다섯 가지는 `studio.test.tsx`와 `features/home/tabs.test.tsx`가 점검한다. 규칙을 건드리는 변경을 하면 그 테스트부터 본다.

## 미술 방향

고급스럽고 양식화된 아이소메트릭 "타이쿤 게임" 느낌의 물류 관제 화면.

- 밝고 부드럽고 깨끗하게: 미색·옅은 회색 세계, **파랑 강조 하나**, 차량·로봇은 **안전 노랑**, 파지·베일은 **크라프트 갈색**. 색은 `theme.ts`.
- 찰흙·장난감 같은 형태: 넉넉한 모서리 둥글림, 어디에나 부드러운 주변 차폐, 닿는 곳의 그림자, 부드러운 환경광, 약간의 따뜻함.
- 눈이 가는 곳에 디테일: 트럭(운전석·창·거울·등·들리는 적재함·바퀴), 지게차(마스트·포크·머리 보호 틀·운전자), 형광 조끼 작업자, 로봇팔, 압축기(투입구·램·결속부·배출 롤러), 파지 더미가 쌓인 섹터 칸.
- 지도식 핀, 흐르는 점선 경로, 퍼지는 선택 고리, 영화 같은 부드러운 카메라 이동.
- 가득 찬 3D 위에 유리 패널: 상단 바, 추이선이 있는 지표 카드 3개, 오른쪽 상세 패널, 왼쪽 아래 6단계 공정 추적(입고 → 차량 인식 → 하역 → 배합 → 압축 → 출하), 오른쪽 아래 탭 표(차량 / 섹터 / 배치 / 베일).
- 전체 흐름: 트럭 도착 → 계중대·번호판 인식 → 배정 섹터 → 하역(적재함 기울임) → 로봇이 배합 → 서버가 정한 압력으로 압축 → 베일 → 지게차가 화면 밖으로. 모두 스스로 움직이고 서로 비켜 가서 겹치지 않는다.

## 값과 연출의 경계 (고정 규칙 2·3을 지키는 방법)

- **서버 값:** 기기 상태, 요약(오늘 베일·평균 수분·가동률), 추이(`GET /plant/history`), 차량·배치·베일의 단계와 값, 알람, 연결 상태. 패널·핀·표는 이 값을 그대로 적는다.
- **연출:** 트럭·지게차·작업자가 "어느 길로 얼마나 빨리" 움직이는지, 쏟아지는 파지, 램의 왕복, 점선. 서버 센서 값이 아니고 화면에 숫자로 쓰지 않는다.
  연출은 서버 단계가 정한 목표까지만 간다(인식 전에는 계중대에서 기다리고, 하역 단계가 와야 적재함을 든다, 출하 단계가 와야 지게차가 싣고 나간다).
- 처음 본 대상이 이미 진행 중이면 지나간 장면을 지어내지 않고 있어야 할 자리에 바로 놓는다. 이미 끝난 대상(출차한 차량, 출하된 베일)은 만들지 않는다.
- **월드 시계:** 모든 움직임은 `Director.step()`이 돌리는 시계 하나를 쓴다. 끊기면 `Sim`이 `step`을 부르지 않으므로 전부 멈춘다. 고리·점선·깜빡임도 이 시계를 쓴다.
  새 움직임을 넣을 때 `performance.now()`나 r3f의 시계를 직접 쓰지 않는다(끊겨도 움직이게 된다). 카메라만 예외다(끊긴 화면도 둘러볼 수 있어야 한다).
- 끊긴 동안에는 `Director.sync()`도 부르지 않는다. 복구되면 store가 REST로 다시 받은 상태가 들어와 이어진다.
- 로봇이 집는 자리·놓는 자리는 서버 관절 값(base 각도)에서 나온다. 섹터 칸과 컨베이어는 그 자리에 맞춰 놓였다(`world/layout.ts`의 `PICK`, `PLACE`). 로봇 배율을 바꾸면 칸 배치도 함께 봐야 한다.

## 모델 (`models.ts`)

- 모델 파일은 `app/public/models/<팩 이름>/`에 두고 `MODELS`에 파일·배율·회전·원점·라이선스·출처·삼각형 수를 적는다. 목록에 없는 파일은 쓰지 않는다. 팩의 라이선스 파일도 같은 폴더에 둔다.
- **팩은 하나로 통일한다.** 지금은 Kenney "Car Kit" 3.1(CC0)이고 **주차된 승용차 6종**에만 쓴다. 불러올 때 텍스처 색을 꼭짓점 색으로 옮기고 차체 색만 스튜디오 색으로 바꿔 공용 재질을 입힌다(`repaint`).
- 트럭·지게차·작업자·나무·소품은 코드로 만든 모형이다. 이유: 적재함·포크·팔다리가 따로 움직여야 하는데, CC0 팩 하나로 이 전부(차량·사람·승용차·나무·소품)를 갖추면서 마디가 나뉜 것을 찾지 못했다
  (Kenney Car Kit에는 덤프트럭·지게차·사람·나무가 없다). 팩을 섞으면 모양이 어긋나므로 섞지 않았다.
- 모델 파일을 못 받아도 화면은 완성되어 있어야 한다. 코드 모형을 먼저 그리고 파일이 오면 바꾼다(`world/ParkedCars.tsx`가 본보기).
- Draco 디코더는 three가 품고 있어 빌드 때 `dist/assets`에 함께 나오고, Draco 모델을 실제로 불러올 때만 내려받는다. Meshopt 디코더는 스튜디오 묶음에 들어 있다.

## 성능 (재서 보고만 한다)

- 측정 화면: `/scene-demo`에서 "스튜디오" 탭. 상단 바에 지금·평균·최저 프레임, 메모리, 경과 시간이 나온다. "연결 끊김 흉내"로 정지 상태도 볼 수 있다.
- 그리는 것: 4096 그림자 지도 하나, 환경광, 후처리(N8AO 주변 차폐, 빛 번짐, 얕은 심도, 색 보정, 톤 매핑, SMAA), 화면 배율 최대 2.
- 그리기 루프는 계속 돈다(`frameloop="always"`). 숨겨지거나 CCTV가 열리면 `never`.
- 측정값과 묶음 크기는 `docs/decisions.md`의 "스튜디오 탭" 항목에 적는다. 이 탭을 유지하기로 하면 그때 화질 단계·프레임 상한을 붙인다.

## 스크린샷

단계별 확인 화면은 `docs/screenshots/studio/`에 둔다(1440×900).
