# app/src/studio — 3D 홈

앱의 **유일한 3D 장면**이다. 홈 맨 위 전환에서 "3D"를 고르면 이 폴더를 lazy로 불러와 홈 화면 전체를 쓴다.
처음에는 "기본" 탭(`scene/`) 옆의 두 번째 탭 "스튜디오"로 **처음부터 새로** 만든 시안이었고, 목표는 **최대한의 시각 품질**이다.
2026-10-14 사용자 결정으로 기본 탭과 `scene/`을 지우고 이것만 남겼다(`docs/decisions.md` "기존 3D 장면 삭제").

## 창작의 자유 (이 폴더에서는 아래를 따르지 않는다)

이 탭은 다음 규칙에 **묶이지 않는다.** 이 폴더에서 작업할 때는 이 파일만 기준으로 삼고, 아래 문서의 시각·배치·성능 규칙은 무시한다.

- 기존 시각 디자인과 디자인 토큰(`styles/index.css`의 색·모서리·그림자, Tailwind 클래스, `components/common`의 패널·카드)
- 옛 장면(`scene/`, 삭제됨)의 세부 성능 원칙(저폴리·불투명 재질만·InstancedMesh 강제·카메라 ±35도 제한 등). 화질 3단계 자체는 따른다(고정 규칙 6)
- 루트 `CLAUDE.md`의 "범위를 벗어난 카메라 조작" 금지, `app/CLAUDE.md`의 화면 기준(태블릿 우선·48dp·호버 금지). 화면 우선순위는 고정 규칙 6을 따른다
- `app/src/features/CLAUDE.md`의 홈 배치 규칙(상단 카드 구성, 단계 바 구성, 정보 배치 기준)
- `docs/dashboard-spec.md`의 화면 모양·성능 원칙 절 (API·값 규칙은 그대로 따른다)

허용되는 것: 후처리(주변 차폐·빛 번짐·심도), 실시간 그림자, 환경광, 투명·유리 재질, 유리 UI, 입자, 자유로운 카메라 이동·확대·회전,
glTF 모델, 새 색·재질·배치·핀·패널. 기존 재질·팔레트·배치·핀·패널은 "정말 그게 최선일 때만" 다시 쓴다.
단, 이 연출은 `high` 단계의 모습이다. 휴대폰·태블릿에서는 고정 규칙 6에 따라 같은 장면을 가볍게 그린다.

## 고정 규칙 (이 탭에 남아 있는 규칙은 이것뿐이다)

1. **3D 없는 홈을 깨지 않고, 메인 묶음을 키우지 않는다.** 3D 코드는 `app/src/studio/`에만 두고, 3D를 고를 때만 lazy로 불러온다. 3D 없는 홈 화면은 three.js를 내려받지 않아야 한다.
   - `features/home`(과 앱 틀)이 정적으로 import해도 되는 것은 three를 import하지 않는 `three/stats.ts`(측정 화면)와 `preload.ts`(미리 받기·포스터 주소)뿐이다. 나머지는 `lazy(() => import('../../studio'))`만 쓴다. 스타일도 `studio.css`(패널 조각과 함께 내려받음)에만 둔다.
   - **조각은 둘이다:** 패널 조각(`index.ts` → LiveStudio·StudioView·overlay, three 없음, 약 16KB gzip)과 3D 조각(`StudioScene.tsx` → Stage·Director·three, 약 450KB gzip).
     패널은 store 값으로 바로 그려지고, 3D 장면은 첫 값이 그려진 뒤에 올린다(`SCENE_START`). 패널 쪽 파일은 three를 정적으로 import하지 않는다(`import type`만): 카메라 지역은 `world/views.ts`, 모델 목록은 `modelList.ts`.
   - 고친 뒤 `npm run build`로 처음 내려받는 묶음(index와 그것이 정적으로 import하는 조각의 합)과 패널 조각에 three가 없는지 확인한다(`loading.test.tsx`가 import 그래프를 본다).
2. **데이터는 기존 store·실시간 계층에서만 온다**(`/scene-demo`에서는 `demo/demoData.ts`의 예시 원본). 프론트에 업무 로직을 두지 않는다:
   번호판 → 회사 → 섹터 배정, 등급, 수분, 배합비, 압력은 서버 값이다. 서버가 아직 주지 않는 숫자가 필요하면 **명세와 모의 서버에 먼저 추가**하거나, 화면에 **"예시 데이터"라고 분명히 표시**한다.
3. **연결 끊김:** 연결이 끊기면 **모든 움직임을 멈추고** "연결 끊김"과 마지막 수신 시각을 보여 준다. 추측을 실제처럼 움직이지 않는다.
4. **조작:** 기존 조작 컴포넌트(`components/controls`)와 권한만 쓴다. 위험 조작은 기기 페이지에 둔다. 비상정지처럼 보이는 버튼을 만들지 않는다.
5. **화면이 숨겨지거나 CCTV가 열리면 그리기를 멈춘다.**
6. **휴대폰 먼저, 그다음 태블릿, 그다음 데스크톱. 스튜디오도 화질 단계(high/standard/low)를 따른다**(2026-10-14 사용자 요청: 모바일이 주 대상).
   배치는 390×844(폰)에서 먼저 성립해야 하고 820×1180(태블릿)·데스크톱으로 넓힌다. 기본 단계는 폰 `low`, 태블릿 `standard`, 데스크톱 `high`이고
   접속 때 프레임 측정으로 한 단계까지 조정한다. `low`는 끊김 없이 도는 것이 유일한 기준이다. 단계별 내용은 아래 "성능" 절.

이 여섯 가지는 `studio.test.tsx`, `loading.test.tsx`(조각 나누기·첫 화면·미리 받기·포스터), `features/home/switch.test.tsx`가 점검한다. 규칙을 건드리는 변경을 하면 그 테스트부터 본다.

## 미술 방향

고급스럽고 양식화된 아이소메트릭 "타이쿤 게임" 느낌의 물류 관제 화면. **시각 기준은 `docs/reference/`의 참고 프레임 10장**이다(모양·분위기만. 상표·아이콘·문구·데이터는 가져오지 않는다).
맞춘 내용과 이유는 `docs/decisions.md`의 "스튜디오 탭: 참고 화면에 맞춘 다듬기", 나란히 놓은 비교는 `docs/screenshots/studio/reference-match/`.

- **색·빛은 첫 시안(753041e)의 것**(2026-10-15 사용자 요청, `docs/decisions.md` "첫 스튜디오 시안의 색·빛으로 되돌리기", 비교는 `docs/screenshots/studio/restore-look/`): 채도 높은 파랑·노랑, 따뜻하고 분명한 해, 또렷하고 부드러운 그림자, 진한 주변 차폐.
- 밝고 깨끗하게, 그러나 **구역은 밝기 단계로 분명히 나뉜다**(2026-10-14 사용자 요청): 렌더 결과로 도로 회청색(#B9C2CE 근처, 흰 차선·가운데 점선) < 바깥 마당 콘크리트 옅은 회색(#E1E1E4 근처) < 건물 바닥 거의 흰색(#F4F4EF 근처, 칠한 통로선·노랑/파랑 바닥 표시). 해가 밝으므로 원색은 그보다 어둡다(마당 #B9BEC7, 아스팔트 #9AA5B4).
  가장자리에 초록 녹지 띠(#C3E4B4)와 풍성한 나무(숲도 맨땅도 아니게). 흰 벽 + 지붕선·모서리·문틀의 파랑 선(#2F6BFF), 벽 위 덮개·컨베이어 틀·압축기는 진한 파랑, 사무동 지붕은 옅은 회색(#D9DEE6).
  섹터 칸은 등급 색(A 옅은 파랑 #E3ECFB, C 옅은 호박색 #FBEBD3, 칸막이 안쪽 아래 띠로 중간 거리에서도 보이게) + 크라프트 파지 더미.
  트럭은 노랑 운전석 + 은색·파랑·흰색 적재함, 회사마다 색 띠 하나(회사 이름은 서버 값, 이름 → 색은 `theme.ts`의 `companyStripe`), 지게차·로봇·작업자 조끼는 **안전 노랑**, 주차 승용차는 흰색·은색 사이에 산호색·청록·남색·파랑 몇 대. 색은 `theme.ts`.
  **전체 채도를 빼지 않는다.** 회색 화면은 연결 끊김에만.
- 빛: 따뜻한 해(2.6)와 또렷하고 부드러운 그림자 + 진한 주변 차폐. 노출을 올리면 밝은 바닥들이 같은 흰색으로 뭉개져 구역이 사라진다(두 번 겪었다: 빛을 바꾸면 렌더 결과 픽셀을 재서 확인하고, 모자라면 바닥 원색을 어둡게 한다).
- 카메라 거리 세 단계(`world/layout.ts`): **wide** 부지 전체(`WIDE_VIEW`), **mid** 한 구역(`AREAS`, 첫 번째가 기본 화면), **close** 고른 대상(`CLOSE_DISTANCE`). 처음에는 wide에서 기본 구역으로 들어온다.
- 화면: 상단 바 하나(로고·검색·탭·지역 전환·실시간 시계·알람·CCTV·사용자). 홈에서는 앱 틀의 상단 바를 넘겨받는다(`components/layout/shellChrome.tsx`, `overlay/Account.tsx`). 화면 이동은 앱의 주 메뉴 하나로 한다: 폰은 화면 아래 탭 바(3D 영역은 그 위에서 끝난다), 태블릿·데스크톱은 왼쪽의 접힌 아이콘 사이드바(펼치면 3D 위에 뜬다). 스튜디오 안에 메뉴를 따로 만들지 않는다(2026-10-15 사용자 요청).
- 패널: 성에 낀 흰 유리, 큰 모서리, 작고 가는 글씨, 카드마다 강조 숫자 하나, 상세 패널은 4~5줄 + "자세히", 표는 개수 붙은 탭 + 상태 알약.
- 선택 표시: 흰 알약 핀(상태 점 ✓ 또는 섹터 적재율 고리 + 이름 + 짧은 값, 아래에 가리키는 점), 고르면 파랑 칩. 멀리서와 폰 폭에서는 섹터 핀이 고리만. 선 상자, 굵게 퍼지는 고리, 고른 차량의 흐르는 점선과 목적지 3D 핀.
- 찰흙·장난감 같은 형태: 넉넉한 모서리 둥글림, 어디에나 부드러운 주변 차폐, 닿는 곳의 그림자, 부드러운 환경광.
- 눈이 가는 곳에 디테일: 트럭(운전석·창·거울·등·들리는 적재함·바퀴), 지게차(마스트·포크·머리 보호 틀·운전자), 형광 조끼 작업자, 로봇팔, 압축기(투입구·램·결속부·배출 롤러), 파지 더미가 쌓인 섹터 칸.
- 배치는 화면 폭 세 단계(`StudioView`의 `useLayout`), **폰부터** 맞춘다:
  - **폰(600px 미만, 기준 390×844)**: 짧은 상단 바(로고 · 3D/대시보드 전환 · 지역 전환 · 연결, 나머지는 "더 보기" ⋯), 옆으로 미는 지표 칩 한 줄(오른쪽 끝을 흐리게 해 밀린다는 것을 알린다), 그 아래 3D가 화면 대부분, 오른쪽 위 작은 지도 도구,
    아래 시트 하나(`PhoneSheet`: 기본은 접혀 공정 막대 + 요약 한 줄, 펼치면 배치 · 차량 · 섹터 · 베일 탭, 고르면 상세). 6단계 추적은 막대 + 지금 단계 이름만(`TrackerBar`).
  - **세로 태블릿(1000px 미만, 기준 820×1180)**: 지표 카드가 한 줄을 채우고, 상세 패널은 오른쪽, 표와 공정 추적이 아래에 쌓인다. 아무것도 고르지 않았을 때 배치 요약은 한 줄 칩(배치 번호 · 배합 · 현재 압력, `Detail`의 `collapsible`)으로 접혀 있고 누르면 펼친다(3D를 덜 가리게). 상단 바의 탭 칸은 줄어들며 옆으로 밀린다.
  - **넓은 화면**: 상단 바, 지표 카드 3개(작은 추이선), 지도 도구, 오른쪽 상세 패널, 왼쪽 아래 6단계 공정 추적(입고 → 차량 인식 → 하역 → 배합 → 압축 → 출하, 둥근 아이콘을 선으로 잇고 오른쪽에 지금 대상 카드), 오른쪽 아래 탭 표(차량 / 섹터 / 배치 / 베일).
  - 어느 폭에서도 패널끼리 겹치지 않는다(펼침 메뉴·시트를 펼친 때는 예외). 배치를 고치면 390×844와 820×1180에서 찍어 본다.
- 전체 흐름: 트럭 도착 → 계중대·번호판 인식 → 배정 섹터 → 하역(적재함 기울임) → 로봇이 배합 → 서버가 정한 압력으로 압축 → 베일 → 지게차가 화면 밖으로. 모두 스스로 움직이고 서로 비켜 가서 겹치지 않는다.

## 구조

```
studio/
├── index.ts            입구(패널 조각). LiveStudio(홈), DemoStudio·PosterStudio(/scene-demo)만 내보낸다. three 없음
├── LiveStudio.tsx      store·실시간 계층 → StudioView. 기존 조작 컴포넌트와 "상세 보기" 링크를 상세 패널에 끼운다. 앱 틀을 넘겨받는다
├── DemoStudio.tsx      예시 원본 → StudioView (조작 없음, "예시 데이터" 표시). PosterStudio: 포스터 찍기용 빈 장면(?poster=1)
├── StudioView.tsx      화면 전체: 유리 패널 + 준비 화면(포스터) + 3D 조각(lazy). three 없음. 데이터는 모두 props (StudioData)
├── StudioScene.tsx     3D 조각의 입구: Director(연출 감독)를 만들어 서버 값을 넘기고 Stage를 그린다. three는 여기서부터
├── preload.ts          3D 파일 미리 받기(정적 파일만: 빌드가 적은 조각 목록, 모델, 포스터)와 포스터 주소. 메인 묶음에 들어간다
├── Stage.tsx           Canvas, 조명·그림자·환경광, 후처리. frozen이면 색을 빼고, paused면 그리기를 멈춘다
├── types.ts            StudioData (서버 값 묶음), RecordLink(공정 기록 화면으로 가는 링크를 앱이 그려 넘기는 함수 모양)
├── quality.ts          화질 단계별 그리기(STUDIO_PROFILES), 기기 종류(폰·태블릿·데스크톱), 단계 고르기(studioTier)
├── useStudioTier.ts    기기 종류·측정값·직접 고른 값 → 지금 단계 (화면 크기가 바뀌면 다시)
├── theme.ts            색 (구역 밝기 단계, 등급 색, 회사 띠 색, 승용차 색)
├── modelList.ts        모델 파일 목록(파일·배율·회전·원점·라이선스·출처·삼각형 수). three 없음 (미리 받기도 읽는다)
├── models.ts           모델 불러오기(draco·meshopt), 색 맞추기
├── studio.css          이 탭 전용 스타일 (st- 접두사). 앱의 Tailwind·토큰을 쓰지 않는다
```

## 값과 연출의 경계 (고정 규칙 2·3을 지키는 방법)

- **서버 값:** 기기 상태, 요약(오늘 베일·평균 수분·가동률), 추이(`GET /plant/history`), 차량·배치·베일의 단계와 값, 알람, 연결 상태. 패널·핀·표는 이 값을 그대로 적는다.
- **연출:** 트럭·지게차·작업자가 "어느 길로 얼마나 빨리" 움직이는지, 쏟아지는 파지, 램의 왕복, 점선. 서버 센서 값이 아니고 화면에 숫자로 쓰지 않는다.
  연출은 서버 단계가 정한 목표까지만 간다(인식 전에는 계중대에서 기다리고, 하역 단계가 와야 적재함을 든다, 출하 단계가 와야 지게차가 싣고 나간다).
- 처음 본 대상이 이미 진행 중이면 지나간 장면을 지어내지 않고 있어야 할 자리에 바로 놓는다. 이미 끝난 대상(출차한 차량, 출하된 베일)은 만들지 않는다.
- **월드 시계:** 모든 움직임은 `Director.step()`이 돌리는 시계 하나를 쓴다. 끊기면 Pacer(`sim/pace.ts`)가 `step`을 부르지 않으므로 전부 멈춘다. 고리·점선·깜빡임도 이 시계를 쓴다.
  새 움직임을 넣을 때 `performance.now()`나 r3f의 시계를 직접 쓰지 않는다(끊겨도 움직이게 된다). 카메라만 예외다(끊긴 화면도 둘러볼 수 있어야 한다).
- 끊긴 동안에는 `Director.sync()`도 부르지 않는다. 복구되면 store가 REST로 다시 받은 상태가 들어와 이어진다.
- 로봇이 집는 자리·놓는 자리는 서버 관절 값(base 각도)에서 나온다. 섹터 칸과 컨베이어는 그 자리에 맞춰 놓였다(`world/layout.ts`의 `PICK`, `PLACE`). 로봇 배율을 바꾸면 칸 배치도 함께 봐야 한다.

## 모델 (`modelList.ts`, `models.ts`)

- 모델 파일은 `app/public/models/<팩 이름>/`에 두고 `modelList.ts`의 `MODELS`에 파일·배율·회전·원점·라이선스·출처·삼각형 수를 적는다. 목록에 없는 파일은 쓰지 않는다. 팩의 라이선스 파일도 같은 폴더에 둔다.
- **팩은 하나로 통일한다.** 지금은 Kenney "Car Kit" 3.1(CC0)이고 **주차된 승용차 6종**에만 쓴다. 불러올 때 텍스처 색을 꼭짓점 색으로 옮기고 차체 색만 스튜디오 색으로 바꿔 공용 재질을 입힌다(`repaint`).
- 트럭·지게차·작업자·나무·소품은 코드로 만든 모형이다. 이유: 적재함·포크·팔다리가 따로 움직여야 하는데, CC0 팩 하나로 이 전부(차량·사람·승용차·나무·소품)를 갖추면서 마디가 나뉜 것을 찾지 못했다
  (Kenney Car Kit에는 덤프트럭·지게차·사람·나무가 없다). 팩을 섞으면 모양이 어긋나므로 섞지 않았다.
- 모델 파일을 못 받아도 화면은 완성되어 있어야 한다. 코드 모형을 먼저 그리고 파일이 오면 바꾼다(`world/ParkedCars.tsx`가 본보기).
- 지금 모델은 모두 Meshopt 압축이다. Meshopt 디코더는 스튜디오 묶음에 들어 있다.
- Draco 모델은 `MODELS`에 `draco: true`로 적는다. 그런 모델을 처음 불러올 때만 DRACOLoader 조각과 디코더를 내려받는다.
  three의 DRACOLoader는 디코더 두 벌(일반용·glTF용) + asm.js 예비본을 가리켜 빌드에 두 벌이 나왔다. `app/vite.config.ts`의 `dracoOnce`가 glTF용 한 벌(wasm + 감싸개)만 가리키게 바꾼다.

## 성능 (화질 단계, 고정 규칙 6)

- 단계 고르기(`quality.ts`, `useStudioTier.ts`): 기기 종류 기본값 — **폰 `low`**(짧은 변 600px 미만), **태블릿 `standard`**(폭 1000px 미만, 또는 긴 변 1366px 이하 + 손가락 입력·모바일 그래픽 칩), **데스크톱 `high`**.
  접속 때 잰 프레임(앱의 `qualityProbe`)은 기본값에서 **한 단계까지만** 움직인다. 사용자가 설정에서 직접 고른 값(`ui.qualityChosen`)은 그대로 따른다. `/scene-demo`에서는 상단 바의 자동·고화질·기본·저사양 버튼, 또는 주소의 `?tier=`.
- 단계별 그리기(`STUDIO_PROFILES`):

  | | low (폰) | standard (태블릿) | high (데스크톱) |
  | --- | --- | --- | --- |
  | 화면 배율 상한 | 1 | 1.5 | 2 |
  | 프레임 상한 | 30 | 30 | 없음(주사율) |
  | 그림자 | 미리 구운 바닥 그림자(진하고 넓게 번짐: N8AO 대신 깊이) + 차량 아래 둥근 그림자 | 2048 그림자 지도 | 2048 그림자 지도 |
  | 주변 차폐 | 미리 구운 바닥 텍스처 | N8AO 낮은 품질·반 해상도 | N8AO 높은 품질 |
  | 후처리 | 없음 (렌더러 톤 매핑만, 끊김 회색은 캔버스 CSS 필터) | N8AO·색 보정·톤 매핑·SMAA | + 빛 번짐·얕은 심도(tilt-shift) |
  | 패널 | 단색(흐림 없음) | 상단 바·상세 패널만 약한 흐림 | 모든 패널 유리 |

- **필요할 때만 그린다**(`frameloop="demand"`): Stage의 Pacer가 화면 주사마다 `sim/pace.ts`를 부른다. 단계의 상한 간격마다 월드 시계를 한 번 돌리고, `Director.motionKey()`가 바뀌었거나
  깨우개(`three/motion.ts`: 카메라가 아직 목표에 닿지 않음, 로봇 관절 값이 마지막으로 그린 자세와 다름, 고른 대상의 고리·점선, 경보등)가 부를 때만 `advance()`로 바로 한 장 그린다.
  아무것도 움직이지 않으면 그리지 않는다(끊긴 동안 5초에 0장, 측정). 작업자의 제자리 몸짓처럼 시계만 따르는 장식은 깨우지 않는다(다른 것이 움직일 때 함께 움직인다).
  새 움직임을 넣으면 `motionKey()`에 넣거나 깨우개를 단다. 넣지 않으면 그 움직임은 다른 것이 움직일 때만 보인다.
- Stage는 `memo`다. 패널이 1초마다 다시 그려져도 무대를 다시 그리지 않게(r3f는 새 배열 props를 바뀐 값으로 보고 한 장을 더 그린다).
- **시작(폰 먼저, 2026-10-15):** 목표는 로그인 뒤 1.5초 안에 지표가 보이는 것. 순서:
  1. 로그인 화면: 홈을 3D로 기억했고 데이터 절약·2G가 아니면, 한가할 때 3D 파일을 미리 받는다(`features/home/useStudioPrefetch` → `preload.ts`). JS 조각은 `modulepreload`(받고 읽기만, 실행 안 함. 받는 중에 로그인해도 `import()`가 이어 쓴다), CSS·모델·포스터는 `prefetch`. **정적 파일만** 받고 API·WebSocket은 부르지 않는다. 조각 이름은 빌드가 `index.html`의 `<meta name="ecocycle-studio-files">`에 적는다(`vite.config.ts`의 `studioFilesMeta`, 개발 서버에는 없음).
  2. 로그인 뒤 홈: 패널 조각(작음)만 받아 패널을 store 값으로 바로 그린다. 그 아래에 준비 화면(빈 장면 포스터 + 옅은 성에 막 + 돌림표 + "3D 장면을 준비하는 중…", z 5, 누르기를 막지 않음). 핀은 첫 장 뒤에 놓는다. 패널이 뜨면 3D 파일 받기를 시작한다(이미 받았으면 그대로).
  3. 첫 값(요약)이 그려진 다음 3D 장면을 올린다(`SCENE_START.waitMs`: 값이 오지 않으면 2.5초 뒤 그냥 올림, 끊긴 채 열면 바로). 장면 만들기가 느린 폰의 메인 스레드를 수 초 잡기 때문이다.
  4. 셰이더를 `renderer.compileAsync`로 미리 컴파일하고 첫 장을 그리면 준비 화면을 걷는다.
- 포스터(`app/public/studio/poster-wide.jpg`, 세로 화면은 `poster-tall.jpg`)는 로그인 전에 받는 공개 파일이다: **빈 장면만**(데이터 없음, 로봇 기본 자세, 번호판·회사 이름·숫자·패널·핀 없음). `npm run poster`(`scripts/poster.mjs`, `/scene-demo?poster=1`)로 찍고, 화면에 글자가 있으면 멈춘다. 장면이 크게 바뀌면 다시 찍는다.
- 첫 화면 시간 측정: `npm run measure:load`(`scripts/loadtime.mjs`): 프로덕션 빌드를 배포처럼(gzip, 다시 확인 캐시) 내주고 390×844 폰, 4G(4Mbps·150ms), CPU 4배 느림으로 로그인 → 지표 숫자, 로그인 → 3D 첫 장을 잰다. 결과는 `docs/decisions.md`.
- 측정 화면: `/scene-demo`(3D 홈만, 예시 데이터). 상단 바에 그린 장 수(지금·평균·최저), 메모리, 기기 종류·단계(측정값), 첫 화면까지 걸린 시간, 그리기 횟수·삼각형 수. 측정값과 묶음 크기는 `docs/decisions.md`.
