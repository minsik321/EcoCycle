# docs/ — 기준 문서

## 파일

| 파일 | 내용 | 누가 고치나 |
| --- | --- | --- |
| `dashboard-spec.md` | 지금 구현의 단일 기준: 화면, API(권한 표 포함), 값 규칙, 인증, 프로토타입 가정, 위험과 대응. 이유는 decisions, 미확인 질문은 questions로 보낸다 | 사용자 확인 후 수정 |
| `decisions.md` | 명세에 없는 구조·기술 결정 기록 | 결정할 때마다 추가 |
| `handover.md` | 프로토타입 전달본: 현재 상태, 시연 방법·계정·시나리오, 화면 안내, 가정, 확인 질문 요약, 한계, 다음 단계 (대표님·서버 담당에게 전달) | 피드백을 받을 때마다 개정 |
| `questions.md` | 미확인 질문의 유일한 목록(대표님 A, 서버 담당 B: 질문, 이유, 현재 가정, 바뀌는 곳) | 질문이 생기거나 답을 받을 때마다 갱신 |

## 규칙

- `dashboard-spec.md`는 대표님·서버 담당과 공유하는 문서다. 구현 편의를 위해 조용히 고치지 않는다. 수정이 필요하면 바꿀 내용을 사용자에게 먼저 보여 준다.
- API 절(인증·조회·실시간·명령·알림·CCTV)을 고치면 같은 작업에서 `shared/` 타입도 고친다.
- 미확인 질문은 `questions.md`에만 둔다(명세에는 ⚠와 질문 번호만). 사용자가 "확인됐다"고 말한 것만 명세 1절 확정 사항 표로 옮긴다.
- 명세 6절 "권한 표"는 `app/src/test/permissionMatrix.ts`와 줄·✓✗까지 같아야 한다(`permissionMatrix.test.tsx`가 비교). 한쪽을 바꾸면 다른 쪽도 바꾼다.
- 가정이 바뀌면 프로토타입 가정 표의 "바뀔 때 고칠 곳" 열을 보고 해당 코드 위치(대개 `app/src/config`)를 함께 고친다.
- 절 번호(1~8절)로 서로 참조하므로 절 순서를 바꾸지 않는다.

## decisions.md 기록 형식

```
## YYYY-MM-DD 제목
- 결정: 무엇을 정했는지
- 이유: 왜
- 상태: 확정 / 가정(확인 필요: 누구에게)
```
