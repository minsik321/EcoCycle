# 프로토타입 전달본 (1단계)

대표님과 서버 담당자에게 드리는 문서입니다. **무엇이 되어 있는지, 어떻게 써 볼 수 있는지, 무엇을 가정했는지, 무엇을 확인해 주셔야 하는지**를 한 곳에 모았습니다.
기준 문서는 `dashboard-spec.md`(개발 플랜과 API 명세)이고, 이 문서는 그 위에서 1단계를 만든 결과를 설명합니다.

- 작성: 2026-10-13, 1단계(핵심 기능) 구현·점검 완료 시점
- 이 문서는 프로토타입을 보여 드린 뒤 피드백에 맞춰 다시 고칩니다.

## 1. 한눈에

| 항목 | 상태 |
| --- | --- |
| 화면 | 로그인, 홈, 섹터, 로봇팔, 컨베이어, 압축기, 알람, 설정, CCTV — **모두 동작** (2D 화면) |
| 서버 | 실서버 대신 **모의 서버**가 명세의 API를 흉내 내며 가짜 센서·관절 값을 흘려 줍니다. 실서버가 같은 명세를 따르면 주소만 바꿔 연결할 수 있도록 만들었습니다. |
| 권한 | 관리자·작업자·열람자 3종(가정)에 따라 화면의 버튼이 나뉘고, 서버도 같은 기준으로 막습니다. |
| 연결 끊김 | 15초 동안 아무 값도 못 받으면 "연결 끊김"과 마지막 수신 시각을 표시하고, 마지막 값을 정상처럼 보여 주지 않으며, 조작을 막습니다. |
| 3D 홈 | **아직 없음** (2단계). 지금 홈은 숫자·상태 카드와 작업 단계 바입니다. |
| 안드로이드 앱 | **아직 없음.** 지금은 웹 브라우저(태블릿 크기 기준)에서 동작합니다. |
| 실제 태블릿 확인 | **아직 못 했음.** 개발 PC의 브라우저에서만 확인했습니다. |

자동 점검 결과: 단위·화면 테스트 379개, 실제 모의 서버를 붙인 통합 테스트 25개가 모두 통과합니다.

## 2. 직접 써 보는 방법

개발 PC에서 아래 순서로 실행합니다 (Node.js 20 이상). 아직 인터넷에 올려 두지는 않았습니다.

```bash
npm install
npm run dev          # 모의 서버(4000번)와 앱(5173번)을 함께 실행
# 브라우저에서 http://localhost:5173 접속
```

**시연용 계정** (모의 서버 전용, 실제 계정이 아닙니다)

| 아이디 | 비밀번호 | 권한 | 해 볼 것 |
| --- | --- | --- | --- |
| `admin` | `mock-admin` | 관리자 | 모든 조작, 수동 모드 전환, 설정 변경 |
| `operator` | `mock-operator` | 작업자 | 시작·일시정지·재개·정지, 알람 확인. 위험 조작은 비활성 |
| `viewer` | `mock-viewer` | 열람자 | 조회만. 조작 버튼이 보이지 않음 |

**상황을 재현하는 시나리오** — `npm run mock -- --scenario=이름` 으로 모의 서버를 따로 띄우고, 다른 창에서 `npm run dev:app`을 실행합니다.

| 시나리오 | 일어나는 일 |
| --- | --- |
| `normal` | 평소 상태. 탱크가 천천히 차고, 로봇팔이 집기→이동→놓기를 반복합니다. |
| `tank-alarm` | 탱크 A1이 곧 80%를 넘어 "주의" 알람이 뜨고, 몇 분 뒤 95%에서 "알람"으로 올라갑니다. |
| `disconnect` | 35초 정상 → 25초 동안 연결은 열려 있지만 값이 오지 않음(반복). 15초 뒤 "연결 끊김"이 뜨는지 볼 수 있습니다. |
| `robot-error` | 25초 뒤 로봇이 오류가 되고 알람이 열립니다. 이때 조작은 거부되고, 45초 뒤 복구됩니다. |
| `token-expiry` | 로그인 토큰이 20초 만에 만료됩니다. 자동으로 갱신되어 끊기지 않는지 볼 수 있습니다. |
| `slow-network` | 모든 응답이 1~4초씩 늦어집니다. |
| `refresh-expiry` | 로그인 유지 토큰이 30초 만에 만료됩니다. 30초 넘게 두었다가 새로고침하면 로그인 화면이 나옵니다. |
| `refresh-reuse` | 로그인 유지 토큰을 누가 훔쳐 다시 쓴 상황을 흉내 냅니다. 토큰이 바뀌고 35초 뒤(응답을 잃은 정상 요청을 봐주는 30초 유예가 지난 뒤) 이전 토큰을 다시 써서 서버가 그 로그인을 끊고, 앱은 로그인 화면으로 돌아갑니다. |
| `server-restart` | 45초 뒤(그 뒤로 2분마다) 서버가 다시 켜진 것처럼 모든 로그인이 사라집니다. 앱은 로그인 화면으로 돌아갑니다. |

로그인 화면의 **자동 로그인**을 켜면 새로고침하거나 브라우저를 다시 열어도(14일) 비밀번호를 묻지 않습니다. 끄면 새로고침은 유지되고 브라우저를 닫으면 다시 로그인합니다. 토큰은 브라우저 저장소에 두지 않고 서버가 심는 보호된 쿠키로 유지합니다.

## 3. 화면 안내

| 화면 | 보이는 것 |
| --- | --- |
| 홈 | 상단 카드(함수율, 전체 적재율, 시스템 상태), 알람 띠, 기기 카드(탱크 4·로봇팔·컨베이어·압축기), 하단 작업 단계 바(집기→이동→놓기→압축). 카드를 누르면 오른쪽에 확대 화면이 열리고 시작·일시정지 같은 간단한 조작이 있습니다. |
| 섹터 | 목록(섹터마다 칸 그림, 주의선)과 섹터별 페이지: 적재율·부피(용량)·수분·등급, 하역 기록(번호판·회사·순중량 t·적재율 변화), 이력 그래프(일·주·월, 이전/다음으로 구간 이동), 주의 기준값 설정, 알람 이력 |
| 로봇팔 | 모드·단계·작업 중 탱크, 조작(수동 모드 전환·탱크 지정 집기는 확인 단계를 거침), 관절 값 표(실시간), 속도 설정, 오류 로그 |
| 컨베이어 / 압축기 | 현재 상태, 조작, 이력 그래프(적재 / 압력·온도), 설정, 알람 이력 |
| 알람 | 열린 알람(실시간)과 최근 7일 이력, 알람 확인, 누르면 해당 기기 페이지로 이동 |
| 설정 | 계정과 할 수 있는 조작, 화질 모드(고화질/기본/저사양, 자동 선택), 앱 정보 |
| CCTV | 상단 버튼으로 열고 카메라를 고르면 영상이 재생됩니다 |

설계 원칙(명세 그대로): 위험한 조작은 기기 페이지에서만, 확인 단계를 거칩니다. "비상정지"는 앱에 만들지 않았습니다(물리 버튼과 현장 안전 장치가 맡습니다). 무게는 쓰지 않고 부피·용량만 보여 줍니다.

## 5. 확인 부탁드립니다

상세한 이유와 "답이 없을 때의 가정"은 `docs/questions.md`에 있습니다. 아래는 요약입니다.

### 가장 먼저 필요한 것

1. **서버는 누가, 언제 만드나요?** (A1, A2) — 3단계(실서버 연동) 시점이 여기에 달려 있습니다.
2. **로그인·토큰·권한 검증을 서버가 해 주나요?** (B1) — 앱은 권한을 판단하지 않고 서버가 막는다는 전제입니다.
3. **관절 각도를 초당 10~20회 줄 수 있나요? 로봇 기종과 축 정보는요?** (B4, B5) — 3D 로봇팔을 실제 움직임에 맞추는 방식이 정해집니다.
4. **명세에 예시가 없는 응답·메시지 형식 합의** (B11~B17) — 제가 이름을 임의로 정한 곳입니다. 아래 "서버 담당자께" 표에 있습니다.

## 6. 지금 못 하는 것, 알려진 한계

- **3D 홈과 핀·카메라 이동**: 2단계에서 만듭니다. 지금 홈은 카드 화면입니다.
- **서버가 값을 주지 않는 항목**: 로봇팔 사이클 통계, 압축기 점검 이력, 설정의 현재값은 임의로 계산하지 않고 "서버가 제공해야 표시할 수 있다"는 안내만 보여 줍니다(B18, B21, B22).
- **안드로이드 앱·푸시 알림**: 아직 없습니다. 지금은 웹 브라우저입니다.
- **실제 태블릿 성능**: 확인하지 못했습니다. 그래프 라이브러리 때문에 처음 불러오는 파일이 큰 편(약 700KB, 압축 시 210KB)이라 저사양 태블릿에서 첫 화면이 느린지는 실기기에서 봐야 합니다.
- **CCTV**: 영상은 공개 테스트 스트림으로 대신합니다. 지연이 있는 HLS만 지원하고 WebRTC와 정지 화면은 아직 없습니다.
- **모의 서버는 운영용이 아닙니다**: 다시 시작하면 값과 로그인이 처음 상태로 돌아갑니다.
- **웹 새로고침 시 재로그인**: 위 2절 참고.
- **인터넷 배포**: 아직 하지 않았습니다. 대표님이 태블릿으로 바로 접속해 보시려면 웹 배포(Vercel 등)를 설정해야 합니다.

## 7. 다음 단계

1. 이 문서와 화면을 보시고 **피드백**(조작 목록, 권한, 홈 수치 등)과 **확인 질문의 답**을 받습니다.
2. **2단계(3D 홈 시안)**: 밝은 저사양 3D 장면, 탱크 수위 연동, 모의 관절 값으로 로봇팔 구동, 핀을 누르면 카메라 이동과 상세 카드. 실제 태블릿에서 초당 30프레임이 안정적인지와 30분 이상 발열·끊김을 확인합니다.
3. 서버가 준비되면 **3단계(실서버 연동)**: 모의 서버를 실제 API로 교체하고 관절 값 매핑(축 수, 영점, 단위)을 확인합니다.
