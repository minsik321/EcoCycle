# 복귀 시 적치 장면 점검

재현: `node app/scripts/yardReturn.mjs` (로컬 Chromium 필요).

실제 앱 렌더러에 브라우저 안에서만 시험용 베일 데이터를 주입했다. 서버나 앱 이동 로직은 변경하지 않았다. 주변 패널 숫자는 시연 데이터이므로 주입한 베일 수와 일치하지 않는다. 판정 수치는 `report.json`을 기준으로 한다.

- 정상 시연 데이터(52초마다 생성, 26초 후 출하)를 1·5·10·30분 시점에 새 장면으로 읽었을 때 적치 수는 각각 1·0·0·0개였다. 실제 모의 서버의 자동 출하는 생성 25초 후다.
- 과부하 조건: 첫 베일 생성 시점을 0초로 두고 20초마다 생성, 출하 없음. 168초에 9개(2단 시작), 328초에 17개(3단 시작), 468초에 24개, 488초에 24개와 대기 1개. 생성 후 8초 이상 지난 베일을 즉시 적치하는 조건을 포함했다.
- 공중 적치 재현: 최초 5초간 운반을 진행하고 프레임·동기화를 600초까지 중단한 뒤 데이터를 반영. 23개 적치, 배출구 1개, 대기 7개. 첫 열 1단은 예약 상태여서 2·3단이 먼저 배치되었다.
- `01-return-floating.png`: 압축기 쪽 첫 적치 열의 바닥 칸이 빈 상태.
- `02-after-placement.png`: 시뮬레이션 7.2초 진행 후 아래 칸에 베일을 놓은 상태. 24개 적치, 대기 7개. 공중 적치 오류와 겹침 모두 0.

스크린샷은 조건을 통제한 재현이며 실제 운영 데이터에서 같은 빈도로 발생한다는 뜻은 아니다. 정상 상태에서 브라우저를 비운 시간만으로 적치 단수가 늘어나는 것은 아니다.
